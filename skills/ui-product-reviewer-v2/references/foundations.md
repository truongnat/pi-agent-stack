# Foundations and benchmarks
Use established systems as cross-checks: Material Design for adaptive component/state thinking, Apple Human Interface Guidelines for platform-native clarity and touch ergonomics, Fluent for systematic tokens/components across form factors, and WCAG 2.2 for accessibility. Do not claim a rule belongs to a benchmark unless certain.

## Token audit
Check semantic color roles, text hierarchy, spacing scale, radii, border widths, elevation, icon sizes/strokes, motion durations/easing, and responsive breakpoints. Flag token proliferation, aliases with no semantic distinction, raw values in product code, and components that bypass tokens.

## Relationship rules
Spacing inside a component should generally be tighter than spacing between components; spacing within a section tighter than between sections. Headings should visually belong to the content they introduce. Alignment edges should be intentionally shared. Use contrast and weight sparingly so the primary path remains obvious.
