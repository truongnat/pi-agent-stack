# Evaluation model
## Evidence
Observed: directly visible in screenshot/code. Inferred: likely based on pattern but not confirmed. Unknown: requires product behavior or user data. Never convert inferred behavior into fact.
## Confidence
High: directly supported by evidence and established usability/design-system principle. Medium: reasonable inference but context could change recommendation. Low: product/user behavior is missing; frame as a question or experiment.
## Heuristic lenses
Check visibility of system status; match with user language and mental models; user control/recovery; consistency; error prevention; recognition over recall; efficiency/flexibility; minimal relevant presentation; useful error recovery; help only where needed. Use them as diagnostic lenses, not a checkbox scorecard.
## Priority
P0 blocks task, causes serious data/action risk, or creates inaccessible critical flow. P1 materially harms common task success. P2 causes recurring friction/inconsistency. P3 polish with limited user impact.
